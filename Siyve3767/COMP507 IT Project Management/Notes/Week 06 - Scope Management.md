> Auto-extracted from [[COMP507 IT Project Management/Lectures/Week 06 - Scope Management.pptx|Week 06 - Scope Management.pptx]]

## What is scope?
- **Project scope** = all the work and processes involved in creating the product — functional requirements, non-functional requirements, regulatory requirements, PM methodology, product + project deliverables, success factors
- **Deliverable** = an artefact produced by the project (hardware/software, planning documents, meeting minutes)
- Scope management = planning, executing, and monitoring/controlling what is (and isn't) part of the project

## Scope management processes
1. **Collect requirements** → requirements document / product backlog (agile)
2. **Define scope** → **scope statement document** (high-level plan; agreement between team and sponsor; prevents **scope creep**; input for time/cost/resource estimates and performance baseline)
3. **Create WBS** → basis for schedule, budget, QA plan
4. **Validate scope** — formal acceptance: customer inspection + sign-off of deliverables; testing (unit, integration, systems, usability, acceptance)
5. **Control scope** — formal testing metrics (bug reports), change control: **change management plan** + **change request form**; manage changes via integrated change control
- Inputs to the scope statement: business case, scope specification, project charter, lessons-learned, policies

## Requirements writing
- Standard terminology: **shall / will / should**
- **Functional requirements** = features (e.g. "the system shall display status messages")
- **Non-functional requirements** = quality attributes: reliability, performance, security, usability, compatibility (e.g. 99.9% availability, 8 transactions/sec, encrypted external comms)

## WBS (work breakdown structure)
- Deliverable-oriented grouping of project work into **phases → tasks → work packages** (decomposition)
- A **work package** = task at the lowest level; appears in only one place; sum of items below; one responsible individual
- For this course: WBS = PMI planning phase + **SDLC** phases (planning → analysis → design → implementation → deployment)
- WBS feeds the schedule, budget, QA plan, and milestone reports
